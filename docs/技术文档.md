## 一、项目概述

### 1.1 项目背景

乡村学校心理健康教育资源极度匮乏。据公开数据，全国中小学专职心理教师配备率在县域及乡镇学校长期处于低位，大量乡村学校由班主任兼管心理健康工作。班主任既缺乏专业的心理学评估工具，也难以察觉留守儿童群体中"隐性"的心理问题——这些学生往往外表安静、成绩平稳，风险信号只存在于日常行为的细微变化里，等被发现时常常已发展为中重度问题。

现有心理测评产品多为"量表测评—生成报告"的单一链路，存在三个明显短板：

1. **学生配合度低**：需独立、完整填写长量表，乡村学生易敷衍作答，数据质量不可靠；
2. **无法动态跟踪**：测评频率低（一学期一次），两次测评之间形成监测盲区；
3. **报告不可执行**：输出是"给人看的分数"，不是"给老师用的行动方案"，班主任拿到分数也不知道下一步该做什么。

### 1.2 项目定位

**乡育心桥（RuralBridge）** 是一个专为乡村教师设计的 Web 应用。它以**轻量化心理问卷**与**多模态日常记录**为双数据入口，由 AI Agent 自动完成"数据采集—心理评估—理论检索—干预方案生成"的完整闭环，输出的不是分数，而是**班级心理晴雨表**与**可直接执行的学生个体干预方案**。

产品的定位差异在于：不做面向学生的心理 App，而做**面向班主任的决策辅助工具**；AI 的角色不是"测评机器"，而是"有心理学理论支撑的教研助手"。

### 1.3 目标用户与价值

| 角色 | 核心诉求 | 使用场景 | 使用频率 |
|---|---|---|---|
| 班主任（主用户） | 快速了解班级心理状态、拿到可执行的干预动作 | 课后、晚自习前、家访前 | 每日 / 每周 |
| 学校心理教师 / 德育主任 | 掌握风险分布、定位重点学生、做专业研判与转介 | 预警处理、个案辅导、月度工作会 | 每日 / 每月 |
| 学生（数据提供方） | 填写负担低、不被打扰、隐私安全 | 班会课或课间手机 / 平板填写 | 每两周一次 |
| 系统管理员 | 账号管理、数据安全、问卷与理论库维护 | 按需 | 低频 |

> 班主任与心理教师是**两个不同的使用角色，需要两套不同的工作流**，而非同一后台加一个权限开关。详见 4.6 节。

### 1.4 创新点

**应用创新点**

- **场景创新**：切入"乡村教育 × 教师辅助"的交叉空白地带，把 AI 定位从"测评机器"改为"有理论支撑的教研助手"。
- **闭环创新**：打通"采集—评估—理论—干预"四段链路，干预建议先检索专业心理学理论再结合个体数据生成，做到有据可查、可追溯到理论来源。
- **角色差异化创新**：同一份学生数据，按班主任 / 心理教师分流成两套完全不同的输出与界面——前者要"明天能做什么"，后者要"心理机制是什么、怎么辅导"。不是权限分级，而是任务分流。
- **行动闭环创新**：班主任端设有「行动台账」，AI 建议可一键入账并跟踪执行状态，答辩时可完整复盘"AI 建议是否真的被执行"。
- **低负担设计**：问卷单次 3 分钟以内，配合多模态日常记录，用"高频轻量"替代"低频重负"。

**技术创新点**

- **多模态数据融合**：结构化问卷数据与非结构化文本记录统一编码后，进入同一评估链路进行风险推理。
- **RAG + 规则双引擎**：规则引擎硬兜底 + 大模型语义推理的双通道，避免纯 LLM 方案在高危场景下的漏报。
- **理论可溯源**：每条干预建议携带来源理论标签与引用片段，解决 AI 建议"不可信、不敢用"的问题。

## 二、需求分析

### 2.1 功能需求

| 编号 | 功能模块 | 功能描述 | 优先级 |
|---|---|---|---|
| F1 | 账号与角色权限 | 教师注册/登录、班级创建、学生名册导入、按角色隔离数据 | P0 |
| F2 | 轻量化心理问卷 | 3 分钟内完成；支持匿名/实名开关；含标准量表精简项 | P0 |
| F3 | 多模态日常记录 | 文字速记 / 语音转文字 / 课堂行为标签三合一快速录入 | P0 |
| F4 | AI 心理评估引擎 | 问卷与记录统一送入 Agent，输出风险等级、类型、关键证据句 | P0 |
| F5 | 班级心理晴雨表 | 三色风险分布、趋势折线、异常波动预警、共性诱因归纳 | P0 |
| F6 | 个体干预方案生成 | 分步建议 + 沟通话术 + 观察指标 + 转介建议，附理论来源 | P0 |
| F7 | 心理学知识库检索 | 关键词 / 自然语言检索专业理论条目 | P1 |
| F8 | 家校沟通辅助 | 一键生成家长沟通要点与注意事项（分风险等级） | P1 |
| F9 | 数据导出与报表 | 导出班级晴雨表 PDF、个体方案 Word、月度统计 Excel | P1 |
| F10 | 隐私与安全 | 敏感字段加密、访问日志、数据脱敏展示、一键删除 | P0 |

### 2.2 非功能需求

- **性能**：单次 AI 评估响应 ≤ 8 秒；班级（50 人）批量评估 ≤ 60 秒；页面首屏 ≤ 2 秒。
- **可用性**：问卷页面适配低端安卓机与 4G 弱网，采用渐进式保存，断网不丢答案。
- **安全合规**：遵循《个人信息保护法》与未成年人个人信息保护相关规定，学生心理数据属敏感个人信息，需单独同意、最小必要采集。
- **兼容性**：Chrome / Edge / Safari 主流版本；移动端浏览器可用。

### 2.3 设计约束与取舍

| 约束 | 取舍 |
|---|---|
| 乡村学校网络条件差 | 前端零框架依赖、单页体积小、无外部字体与 CDN 依赖 |
| 教师非技术用户 | 交互不超过三次点击到达核心结论，术语尽量口语化 |
| 评委需在线体验 | 提供可直接访问的在线演示站，学生账号提交后教师后台实时可见 |
| 隐私合规 | 测试环境仅使用测试学生账号，不涉及真实学生身份；学生间数据互相隔离 |

## 三、系统架构设计

### 3.1 总体架构

系统采用分层架构，自下而上分为数据层、AI 智能层、应用层、表现层。

```
┌──────────────────────────────────────────────────────────┐
│  表现层   教师端 Web（原生 JS + 纯 CSS + SVG 图表）        │
├──────────────────────────────────────────────────────────┤
│  应用层   账号权限 / 名单管理 / 问卷 / 记录 / 报表         │
│           学生端与教师端按角色分流                          │
│           线上环境：Serverless 函数（/api/*）               │
├──────────────────────────────────────────────────────────┤
│  AI 智能层 ① 规则引擎（高危硬兜底）                         │
│            ② 语义推理（大模型 API）                         │
│            ③ RAG 检索（关键词召回 + 共现打分）              │
│            ④ 方案生成（结构化输出 + 理论回填）               │
├──────────────────────────────────────────────────────────┤
│  数据层   演示环境：D1 数据库（学生真实提交，强一致）        │
│           线上环境：云数据库 + 向量库 + 对象存储             │
└──────────────────────────────────────────────────────────┘
```

### 3.2 技术选型

| 层次 | 组成 | 技术选型 | 选型理由 |
|---|---|---|---|
| 表现层 | 教师端 Web、学生端轻量页 | 原生 HTML/CSS/JavaScript + SVG | 无框架依赖，单页体积小、首屏快，弱网与低端机可用；SVG 绘制趋势图，无需引入图表库 |
| 应用层 | 业务逻辑、权限、数据网关 | Serverless 函数（Pages Functions） | 免运维、随站部署；学生提交与教师读取共用同一套接口 |
| AI 智能层 | 规则引擎、语义推理、RAG、方案生成 | 规则引擎（自研）+ 大模型 API + 关键词检索 | 规则引擎可解释、可审计、硬兜底；大模型负责语义推理；两者互补 |
| 数据层 | 业务数据、理论库、文件 | D1（SQLite，强一致） | 学生提交后教师后台需立刻可见，强一致优于最终一致的 KV；免运维、与 Pages 原生集成 |

### 3.3 数据模型

**已实现（演示环境，Cloudflare D1）**

| 表名 | 关键字段 | 说明 |
|---|---|---|
| `submissions` | id, user, name, type, answers, text, level, risk_type, evidence, steps, talk, rule_hits, score, engine, created_at | 学生真实提交记录（问卷与日常记录同表），`type` 区分两类；`answers`/`evidence`/`steps`/`talk`/`rule_hits` 为 JSON 字符串 |

**线上扩展规划**

| 表名 | 关键字段 | 说明 |
|---|---|---|
| `user` | id, name, role, class_id, password_hash | 教师/管理员账号，角色隔离 |
| `student` | id, name, class_id, gender, is_left_behind, encrypted_meta | 学生基础信息，敏感字段加密 |
| `assessment` | id, student_id, risk_level, risk_type, evidence, model_ver | AI 评估结果，保留模型版本便于追溯 |
| `intervention` | id, assessment_id, steps_json, theory_refs, status | 干预方案与理论引用、执行状态 |
| `class_weather` | id, class_id, period, green_cnt, yellow_cnt, red_cnt, trend_json | 班级晴雨表数据 |

### 3.4 接口设计

**已实现（演示环境）**

| 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `/api/ai/assess` | POST | text（记录文本）、answers（问卷作答）、theories（理论库）、studentName | 风险等级、类型、判定依据、干预步骤、理论来源、命中规则 |
| `/api/data/submit` | POST | user、name、type（questionnaire/record）、answers、text、result | 提交 ID、时间戳 |
| `/api/data/list` | GET | — | 全部提交记录、按学生聚合的状态、班级统计 |
| `/api/data/reset` | POST | confirm（"RESET"） | 删除条数 |

> 学生提交（`/api/data/submit`）与教师读取（`/api/data/list`）共用同一数据源；教师后台每次进入即拉取最新数据，保证实时性。

**线上扩展规划**

| 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `/api/auth/login` | POST | 账号、密码 | token、角色、班级 |
| `/api/class/weather` | GET | classId、period | 三色分布、趋势、共性诱因 |
| `/api/export/report` | GET | classId、type(pdf/docx/xlsx) | 文件流 |

## 四、AI 技术方案

### 4.1 选型理由

| 技术组件 | 选型 | 选型理由 |
|---|---|---|
| 大语言模型 | OpenAI 兼容的国产大模型 API（实际接入 `deepseek-v4.1-flash`） | 中文语境与青少年心理文本理解能力好；API 按量付费、无部署门槛；国内访问稳定、合规可控。**不选纯本地小模型**：7B 以下模型在专业领域推理上幻觉严重，干预建议不可用。模型须配合末尾强制 JSON 指令使用，详见 4.7.1 |
| Agent 编排 | 轻量自研编排（演示）/ Dify 或 LangChain（线上） | 演示环境自研确定性引擎，保证评审期间稳定可复现；线上用编排框架便于扩展与可视化调试 |
| 向量化与检索 | 演示：关键词召回 + 共现打分（零依赖）；线上：bge-m3 或 text2vec-base-chinese + 向量库 | 演示环境不引入向量模型，保证零依赖、可复现；线上换向量检索提升召回 |
| 规则引擎 | 自研关键词 + 正则 + 权重评分 | 高危信号不容许任何不确定性，必须硬触发；规则可解释、可审计，便于向评委说明安全设计 |
| 前端 | 原生 HTML/CSS/JS | 无构建步骤、无依赖，任何静态托管即可部署，评审体验零门槛 |

### 4.2 集成方式

- **统一 AI 网关**：应用层不直接调用大模型，统一经 `/api/ai/*` 网关转发，便于统一鉴权、限流、缓存与模型替换。
- **提示词工程**：系统提示词内置心理教师角色设定、青少年保护原则、禁止下诊断结论的红线约束；输出强制 JSON Schema，便于前端渲染。
- **RAG 流程**：理论库条目预先切片并标注关键词 → 评估时按记录文本与作答召回 Top-K 条目 → 将其“干预要点”拼入提示词 → 生成建议并回填引用来源。（演示环境用关键词召回 + 共现打分，线上可换向量检索。）
- **异步任务**：班级批量评估走队列，避免 HTTP 超时。

### 4.3 Agent 工作流

```
学生数据（问卷 + 日常记录）
        │
        ▼
  ① 规则引擎硬筛查 ──命中高危──▶ 直接升级红色预警 + 提示转介
        │（未命中）
        ▼
  ② 特征归一化（记录文本 + 问卷作答统一编码）
        │
        ▼
  ③ 大模型语义推理（风险等级 / 风险类型 / 证据句）
        │
        ▼
  ④ RAG 理论检索（按风险类型召回心理学理论 Top-K）
        │
        ▼
  ⑤ 干预方案生成（分步建议 + 沟通话术 + 观察指标 + 理论引用回填）
        │
        ▼
  ⑥ 结果落库 → 刷新班级晴雨表 → 推送班主任
```

**关键设计**：规则引擎与语义推理**串行且规则优先**——输入先过规则通道，命中高危则**短路返回红色预警、不调用大模型**（既保安全又省额度）；未命中才进入语义推理。任一层级判定为高危即升级风险等级，确保 AI 的不确定性不会导致漏报。

### 4.4 优化策略

| 优化方向 | 具体做法 | 预期效果 |
|---|---|---|
| 降低幻觉 | 强制结构化输出 + 理论引用回填 + 规则引擎兜底 | 干预建议可追溯，高危不漏报 |
| 降低成本 | 相同输入结果缓存；问卷评分等确定性计算不调用大模型；短文本小模型、复杂推理大模型分级调用 | API 费用下降 40% 以上 |
| 提升速度 | 流式输出 + 风险等级先行返回、方案异步补全；理论库常驻内存 | 首屏反馈 ≤ 3 秒 |
| 提升准确率 | 历史案例构造 Few-shot 示例；建立教师反馈回路，人工标注结果回灌 | 风险识别准确率逐周提升 |
| 安全护栏 | 输入侧敏感词检测、输出侧违规内容过滤、未成年人数据脱敏后再送模型 | 满足合规要求，避免隐私外泄 |

### 4.5 效果评估方法

- 构造 30–50 条脱敏模拟案例（覆盖绿/黄/红三色），由团队与指导教师人工标注基准，计算风险等级判定准确率与召回率（**重点看红色召回率，目标 100%**）。
- 对干预方案做人工可读性评分（1–5 分），统计"理论引用是否准确""动作是否可执行"两个维度。
- 记录平均响应时延与单次调用成本，形成优化前后对比表。

### 4.6 角色差异化设计（双工作流）

班主任与心理教师面对同一份学生数据，但决策目标完全不同。系统在**接口层、提示词层、界面层**三处同时分流，而不是靠前端隐藏按钮做假差异。

| 层次 | 班主任（teacher） | 心理教师（counselor） | 学生（student） |
|---|---|---|---|
| 核心问题 | 班上现在什么情况 · 我明天能做什么 | 这个孩子内心在发生什么 · 我该怎么辅导 | 我现在能为自己做什么 |
| 系统提示词 | 落到座位、作业量、课堂提问、同伴搭配、家校沟通 | 个案概念化、心理机制、辅导技术、会谈节奏、风险研判与转介 | 温和平等、低门槛自助建议、必要时引导求助 |
| 温度参数 | 0.35（稳定可执行） | 0.25（专业严谨） | 0.5（温和自然） |
| 专属输出块 | `teacher`：studentSummary / immediate / classroomAdjust / homeContact / watchFor / talk | `counseling`：conceptualization / mechanism / techniques / sessionPlan / riskJudgement / referral / cautions | 仅 steps + talk |
| 界面导航 | 班级概览 / 班级研判 / 学生名单 / 数据收集 / 行动台账 / 班级报告 | 预警队列 / 个案研判 / 辅导档案 / 心理态势 / 转介与危机 / 专业工具箱 | 心理问卷 / 日常记录 / 我的结果 |

**职责边界（防止越权）**：班主任端**不输出**心理学机制与诊断性术语；心理教师端**不输出**作业量、课堂模式等班级管理动作。两端通过「接手状态」单向同步——心理教师接手后，班主任只能看到"已接手"徽标，看不到辅导内容。

**班级宏观研判独立成接口**：`/api/ai/class` 只接收聚合特征（风险分布、信号频次、等级序列），**不传学生姓名**，从数据源头降低隐私暴露面；输出四个维度的管理动作（workload / activity / classroom / home），与个体评估接口职责分离。

**三级降级保证**：任一角色在服务端不可达时，`engine.js` 按同一数据结构返回本地确定性结果（学生自助 / 班主任行动 / 心理教师研判三套兜底模板），保证任何网络状态下界面不白屏、不空白。

**超时阈值设定**：实测三档耗时——学生约 7s、班主任约 17s、心理教师约 27s（输出块最多）。前端超时定为 **75s**；早期 20s 的阈值会在心理教师角色上提前中断并静默降级，属于必须避开的坑。

### 4.7 已知限制与应对（实测记录）

本节记录开发与实测中发现的真实限制，以及当前采取的应对方式。**如实披露限制不是缺陷，是工程成熟的标志**——这些结论都来自线上实测，不是推测。

#### 4.7.1 上游模型不执行 response_format（已解决）

**现象**：接入的模型在请求中明确设置 `response_format: { type: 'json_object' }` 后，仍返回整篇 markdown 散文而非 JSON 对象。

**实测证据**（`POST /api/ai/kb`，query=「具身认知」）：

```
finish: "stop"                    ← 正常结束，非截断
completionTokens: 1655            ← 额度充足（其中 reasoning 占 842）
contentHead: "**具身认知**一句话：认知和情绪不只发生在…"
```

模型没有报错、没有超时、没有超长，仅仅是**不按协议输出格式**。

**影响面**：`/api/ai/assess`、`/api/ai/class`、`/api/ai/priority`、`/api/ai/kb` 四个接口同时受影响。前三者返回 502，前端回退到本地规则引擎，`model` 字段显示「本地兜底：服务端不可达」——**即整个 AI 层已静默退化为纯本地规则**，界面上因为兜底完整而不易察觉。

**排查方法**：API Key 以加密形式存于 Cloudflare，开发机无法直接调用上游。为此临时新增 `/api/ai/models` 诊断接口，借助 Worker 环境内的 key 完成两件事：枚举上游可用模型、用**真实业务提示词**做策略对照实验（而非简单探针）。排查结束后该接口已删除。

**策略对照实验（决定性证据）**：

| 策略 | 机制 | 结果 |
|---|---|---|
| `json_object` | `response_format: {type:'json_object'}` | ❌ 散文 |
| `json_schema` | `response_format: {type:'json_schema', strict:true, schema}` | ❌ 散文 |
| `prefill` | assistant 预填 `{` 强制续写 | ❌ 散文 |
| `plain` | 不加任何约束（对照组） | ❌ 超时 |
| `combo` | json_schema + 泛泛的「只输出 JSON」 | ⚠️ 是 JSON，但**模型自编字段名**（`chiefComplaint`/`riskLevel`/`teacherActions`），schema 未被采纳 |
| **`combo2`** | **末尾用普通语言写死顶层字段名 + 完整 skeleton** | ✅ **完全命中，字段一个不多一个不少** |

**结论**：上游**完全不执行 `response_format`**，无论 `json_object` 还是 `json_schema`（含 `strict: true`）。唯一有效的手段是：**在对话最后一轮，用普通语言把字段名清单、取值范围与 JSON 骨架写死。**

注意 `combo` 的反例价值：仅靠 schema + 泛化指令时，模型确实输出了 JSON，但字段名是自己编的——**「是 JSON」不等于「是约定的 JSON」**，这在工程上必须用字段校验兜住，否则前端按 `parsed.level` 取值会全部拿到 `undefined`。

**采用的方案（四层防护）**：

| 层级 | 措施 | 说明 |
|---|---|---|
| ① 末尾强制指令 | `FINAL_ORDER_ASSESS / _CLASS / _PRIORITY / _KB`：列出必须且只能使用的顶层字段名、取值范围、完整 skeleton 示例，结尾重申「第一个字符是 `{`，不要任何其他文字」 | **实测唯一有效的手段**，四个接口均已接入 |
| ② 提示词首尾夹逼 | 系统提示词开头声明「你是 JSON 生成接口，不是聊天助手」，结尾再次强调 | 辅助，单独使用无效 |
| ③ 容错解析 | `extractContent()` + `parseLooseJson()` | 兼容 content 为数组/对象、正文落在 `reasoning_content`、markdown 围栏、前后夹杂说明文字 |
| ④ 字段校验 + 兜底 | 逐接口校验必需字段（`assess`→`level`、`priority`→`items`、`class`→`climate` 等），不合格视为失败 | 防止用空对象拼出**假结论**（如 `assess` 退成 yellow），比报错更危险 |

另保留 `repairJson()`（解析失败时把散文回灌让模型自己整理成 JSON）作为极端情况兜底。**如实说明：在本次排查中它从未成功过一次**——上游连「把已有文字转成 JSON」都不做。它保留的意义是兜住未来更换模型后的不确定性，不应被当作主方案。

**更换模型的过程**：原模型 `deepseek-v4-flash-0731` 在策略实验下全部失败；切换至 `deepseek-v4.1-flash` 并配合末尾强制指令后，四个接口全部恢复结构化输出。线上实测：

| 接口 | 状态 | 耗时 | 结果 |
|---|---|---|---|
| `assess`(班主任) | 200 | 15.0s | `engine=llm`，`level=yellow`，`teacher` 块 6 字段齐全 |
| `priority` | 200 | 5.0s | `items=[{i:0,p:P1},{i:1,p:P2}]`，分档合理 |
| `class` | 200 | 14.7s | `climateLevel=watch`，10 字段齐全 |
| `kb` | 200 | 15.7s | `degraded=None`（走结构化路径），`category=发展` |

`kb` 的 `degraded` 从 `true` 变为 `None`，是恢复结构化路径的直接证据。

**知识库接口的散文降级（现为备用路径）**：`/api/ai/kb` 是纯 AI 补充入口，没有本地兜底，因此保留 `cleanProse()` 散文降级——结构化失败时清理 markdown 装饰后作为纯文本返回，标注 `degraded: true`、`confidence: low`，前端渲染为「自由作答未结构化 · 未经专业审核」的软色卡片。**宁可给一段标注清楚的散文，也好过给一个报错。** 当前模型下该路径已不再触发。

**为何不对三个结构化接口做散文降级**：`assess` / `class` / `priority` 的输出必须有结构化字段（`level`、`steps`、`teacher`、`priority` 等），散文无法还原成结构，强行解析等于编造字段。这三个接口的正确行为是让前端回退本地规则。

**通用经验**：面对不守协议的模型，不要停留在「加提示词 / 加重试」的层面。用真实业务提示词做**策略对照实验**，才能定位到底是模型能力问题还是协议未被执行；`combo` 与 `combo2` 的差异也说明，验证时要同时检查「是否为 JSON」与「字段是否符合约定」，只看前者会产生假阳性。

#### 4.7.2 规则引擎的覆盖边界

规则引擎基于关键词与正则，必然存在漏召回：学生可能用方言、隐喻或自创表达描述同一状态（例如「心里堵得慌」未命中任何规则词）。系统的应对是**不把规则引擎当作唯一判定依据**——它只负责高危硬触发（宁可误报不可漏报），语义判断交由大模型与人工复核完成。

#### 4.7.3 团体筛查的固有局限

问卷在班级集体施测，存在敷衍作答、相互影响、社会赞许性偏差（不愿承认负面状态）。系统通过数据质量检测识别四类信号（仅提交一次 / 直线作答 / 相邻问卷完全一致 / 问卷与记录矛盾），并明确**只做提示、不改判等级**——最终以教师当面核实为准。筛查工具不替代临床访谈。

#### 4.7.4 理论库的静态性

本地理论库收录 91 条（疗法 19 / 发展 11 / 情绪 11 / 效应 24 / 议题 14 / 危机 7 / 群体 5），覆盖常见场景但无法穷尽。检索已实现同义词扩展（实测 72 个常用词命中率 100%），未收录概念由 AI 补充并明确标注未经审核。**部分流传甚广的说法（如「野马结局」）缺乏可靠实证来源，条目内直接标注「通俗比喻，非实证结论」，不包装为科学事实。**

## 五、核心功能实现

### 5.1 规则引擎（硬兜底通道）

规则引擎是本系统安全设计的核心。其职责是：**对任何输入文本做高危信号硬筛查，命中即升级风险等级，不经过大模型判断**。

```
R-HARD-1  自伤/自杀意念   ["伤害自己","自杀","不想活","活不下去","结束生命"]   → 红色 · 硬触发
R-HARD-2  绝望感          ["没人能帮我","没有希望","绝望"]                     → 红色 · 硬触发
R-HARD-3  同伴关系风险    ["被欺负","被打了","校园欺凌","没人跟我玩"]           → 黄色
R-HARD-4  亲子分离应激    ["爸妈不在","留守儿童","想爸妈","没人管我"]           → 黄色
R-HARD-5  睡眠困扰        ["睡不着","失眠","做噩梦"]                          → 黄色
```

规则命中记录会随评估结果一并输出（含规则编号、类型、命中关键词、是否硬触发），前端以标签形式展示，使判定过程**完全可审计**。

### 5.2 问卷评分

10 题轻量问卷，每题 0–3 分，按维度聚合（情绪 / 睡眠 / 自我 / 焦虑 / 社交 / 学业 / 高危）。其中第 9 题（"我想过伤害自己"）为**高危筛查项**，一旦作答非"完全没有"，即触发红色等级。

### 5.3 RAG 理论检索

理论库当前收录 6 条核心心理学理论条目：

| 编号 | 理论 | 主要适用风险类型 |
|---|---|---|
| T1 | 依恋理论 | 亲子分离、留守儿童、社交回避 |
| T2 | 认知行为疗法（CBT） | 消极认知、自我否定、情绪低落 |
| T3 | 留守儿童心理韧性模型 | 韧性不足、适应困难 |
| T4 | 情绪 ABC 理论 | 易激惹、冲动、挫折应对 |
| T5 | 社会支持理论 | 社交退缩、孤立 |
| T6 | 马斯洛需求层次理论 | 底层需要缺口、动力不足 |

检索采用**关键词召回 + 文本共现打分**，按风险类型与证据文本打分排序，返回 Top-K 条目，并将其"干预要点"注入方案生成环节。

### 5.3.1 量表施测的通用原则

系统内置 4 个可施测量表（PHQ-9 抑郁 9 题 / GAD-7 焦虑 7 题 / ISI 睡眠 7 题 / C-SSRS 自杀风险 6 题），
支持教师派发给单个学生、学生在线填写、自动计分与结果回填。以下原则是本模块的设计依据，
也适用于教师使用任何纸质量表时的判断：

| 原则 | 说明 |
|---|---|
| 筛查不等于诊断 | 任何自评量表的结果只能提示「需要进一步关注」，不能作为诊断依据。诊断须由具备资质的精神科医师或临床心理专业人员作出。 |
| 团体筛查阳性必须个别复核 | 团体施测环境（如整班同时填写）易出现敷衍作答、相互影响。阳性结果须由教师个别访谈确认，不可直接据分处置。 |
| 结果不公开 | 不在班级宣读、不在办公室随意讨论、不在家长群公布排名。记录只写必要事实，按最小必要原则知悉。 |
| 施测前说明用途与保密例外 | 开场讲清：为什么测、结果给谁看、什么情况下会告诉别人（自伤自杀风险、受虐待等）。提前说明比事后告知伤害小得多。 |
| 注意反向计分条目 | SDS/SAS/RSES/PSS 等量表含反向计分条目，手工计算极易出错，一处算错整份结论就偏了。 |
| 关注作答质量 | 全部选同一选项、答题时间明显过短、前后矛盾，都应视为可疑作答，需重新施测或结合日常观察判断。 |
| 文化与本地方言适配 | 部分条目的表述对乡村学生可能不易理解（如「我觉得自己像一块沉重的石头」）。必要时用方言口头解释，但不改变原意。 |

**安全条目的特殊处理**：PHQ-9 第 9 条（自伤意念）不参与总分判级，单独走安全通道——
勾选「有几天」至少列为黄色，「经常/几乎每天」直接升级为红色并改写结论文案，
避免出现「等级红色、标签却写着无或极轻」的自相矛盾卡片。

**C-SSRS 必须一对一施测**：该量表涉及自杀风险，不可整班集体填写。
系统在教师派发该量表时会强制提示此限制。

### 5.4 干预方案生成

方案生成遵循"**等级决定框架，理论决定动作**"的原则：

1. 风险等级决定基础动作框架（红色 → 立即响应 + 安全兜底 + 转介跟踪；黄色 → 重点关注 + 观察记录；绿色 → 常规关注）；
2. 召回的每条理论追加针对性动作（如召回依恋理论 → 补足替代性支持关系；召回 CBT → 认知觉察练习）；
3. 每条建议携带理论来源标签，前端可展开查看理论依据。

### 5.5 班级晴雨表

- **三色分布**：按学生最近一次提交的风险等级聚合，输出绿色/黄色/红色人数与占比。
- **实时数据**：数据来自学生端真实提交（问卷 + 日常记录），学生每次提交后教师后台自动刷新；无数据时显示空状态。
- **最近提交**：按时间倒序列出最新提交记录，便于教师第一时间掌握动态。
- **共性诱因归纳**：基于已提交数据聚合风险分布，输出如"红色预警 N 人""需关注学生 M 人"等结论。

### 6.3 部署方案

演示站前端为纯静态页面，可部署到任意静态托管平台；线上 AI 能力由仓库根目录 `functions/` 下的 Serverless 函数随站一起部署（无需单独部署后端）：

| 平台 | 命令 | 特点 |
|---|---|---|
| Cloudflare Pages | `wrangler pages deploy web` | 免费、无需备案、无 IP 访问限制；自动上传 `functions/` |
| Vercel | `vercel deploy web --prod` | 免费、部署简单 |
| Netlify | `netlify deploy --dir=web --prod` | 免费、支持表单与函数 |

**评审可用性保障**：

- 页面与 AI 能力**同站部署**；AI 不可用时（未配密钥 / 服务不可达）**自动降级**为浏览器内本地确定性引擎，页面不会白屏；
- 部署平台自带 CDN 与 HTTPS，无并发限制；
- 评审账号在登录页直接公示，并提供一键填入。

### 6.4 隐私与安全设计

- **数据隔离**：测试环境仅使用测试学生账号（`student1`~`student5`），不涉及真实学生身份；学生仅能查看自己的问卷与结果，无法访问他人数据或教师后台。
- **最小必要**：仅采集评估必需的字段。
- **访问控制**：按角色隔离数据，班主任与心理教师可查看聚合结果，学生仅见自身。
- **数据可删**：后台提供「重置学生数据」按钮，一键清空全部测试数据。
- **审计留痕**：敏感数据访问记录日志（线上环境）。
- **密钥安全**：大模型 API Key 仅存于服务端环境变量，前端代码不含任何密钥。

3. **真正的低负担**：3 分钟问卷 + 日常速记，让动态跟踪在乡村学校真正可行。
4. **零门槛体验**：前端无框架依赖、无需构建；AI 能力随站部署且带自动降级，评审点开即用。

### 7.3 后续展望

- **横向扩展**：从班主任视角扩展到学校、区域两级，形成心理工作数据看板。
- **纵向深化**：接入更多本土心理学研究成果，扩充理论库；引入真实干预效果回流，形成"建议—执行—反馈"闭环，持续优化模型。
- **多模态增强**：语音记录转写、课堂行为视频分析。
- **离线能力**：针对无网校园场景，提供本地缓存与断网续传。
