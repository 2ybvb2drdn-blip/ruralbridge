# 乡育心桥 · 回归测试

无浏览器依赖的前端测试。用 [jsdom](https://github.com/jsdom/jsdom) 加载真实页面，
按 `index.html` 的实际顺序执行全部脚本，然后断言渲染结果与引擎逻辑。

## 为什么不用浏览器

真实浏览器需要 Chrome/Playwright，安装体积大、启动慢、CI 环境常缺依赖。
本项目所有逻辑都在前端脚本里（问卷评分、规则引擎、RAG 检索、PDF/Excel 生成、
台账与角标），用 jsdom 加载同一份代码就能覆盖绝大部分行为，
且跑完整套只要十几秒。

渲染层面的样式（布局、媒体查询）不做像素级断言，只校验 CSS 规则与类名存在——
这类问题留给人眼在浏览器里确认，用 jsdom 硬测性价比很低。

## 安装与运行

```bash
cd tests
npm install          # 只依赖 jsdom
npm test             # 跑全部
npm test -- pdf      # 只跑文件名含 pdf 的
node run-all.js --list   # 列出所有测试
```

## 编写约定

每个测试文件是**独立的 node 脚本**，不共享环境，自己输出一行统计：

```
通过 69 / 失败 0 全部通过 ✅
```

`run-all.js` 靠正则 `通过 (\d+) / 失败 (\d+)` 汇总，
所以新增测试请保持这个输出格式，否则会被判为崩溃。

单条断言用：

```js
let pass = 0, fail = 0;
function ok(name, cond, detail) {
  if (cond) pass++;
  else { fail++; console.log('  ✗ ' + name + (detail ? ' — ' + detail : '')); }
}
```

失败时务必把**实际值**带上，否则只能靠猜。

## 路径约定

测试读的是 `../web`，用 `path.join(__dirname, '..', 'web')` 定位，
不写绝对路径，保证换机器、换目录都能跑。

## 测试数据的坑

**不要写死日期。** 曾经把截止日固定为 `2026-10-25`，第二天测试就失败——
动作因过期落到「已逾期」栏，而断言在查「待执行」栏。用相对日期：

```js
const dueD = new Date(Date.now() + 86400000).toISOString().slice(0, 10);
```

**不要让测试数据自相矛盾。** 例如入库等级写 `green`，但作答按当前规则重算
实为 `yellow`，会触发「等级偏低」检测——那是代码正确报警，不是 bug，
但会让「干净数据不误报」这类断言失败。

**注意哪些行为是设计而非缺陷。** 「本地已收录时不调 AI」这条断言曾经
把 bug 当成正确行为：它导致 AI 补充按钮点下去毫无反应，测试却全绿。
写断言前先问「用户期望的是什么」，而不是「代码现在做了什么」。
