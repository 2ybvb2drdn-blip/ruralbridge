## 一、项目概述

### 1.1 项目背景

乡村学校心理健康教育资源极度匮乏。据公开数据，全国中小学专职心理教师配备率在县域及乡镇学校长期处于低位，大量乡村学校由班主任兼管心理健康工作。班主任既缺乏专业的心理学评估工具，也难以察觉留守儿童群体中"隐性"的心理问题——这些学生往往外表安静、成绩平稳，风险信号只存在于日常行为的细微变化里，等被发现时常常已发展为中重度问题。

现有心理测评产品多为"量表测评—生成报告"的单一链路，存在三个明显短板：

1. **学生配合度低**：需独立、完整填写长量表，乡村学生易敷衍作答，数据质量不可靠；
2. **无法动态跟踪**：测评频率低（一学期一次），两次测评之间形成监测盲区；
3. **报告不可执行**：输出是"给人看的分数"，不是"给老师用的行动方案"，班主任拿到分数也不知道下一步该做什么。

### 1.2 项目定位

**乡育心桥（RuralBridge）** 是一个专为乡村教师设计的 Web 应用。它以**轻量化心理问卷**与**多模态日常记录**为双数据入口，由 AI Agent 自动完成"数据采集—心理评估—理论检索—干预方案生成"的完整闭环，输出的不是分数，而是**班级心理晴雨表**与**可直接执行的学生个体干预方案**。

产品的定位差异在于：不做面向学生的心理 App，而做**面向班主任的决策辅助工具**；AI 的角色不是"测评机器"，而是"有心理学理论支撑的教研助手"。

### 1.3 目标用户与价值

| 角色 | 核心诉求 | 使用场景 | 使用频率 |
|---|---|---|---|
| 班主任（主用户） | 快速了解班级心理状态、拿到可执行的干预动作 | 课后、晚自习前、家访前 | 每日 / 每周 |
| 学校心理教师 / 德育主任 | 掌握全校风险分布、定位重点班级与重点学生 | 月度工作会、期初期末 | 每月 |
| 学生（数据提供方） | 填写负担低、不被打扰、隐私安全 | 班会课或课间手机 / 平板填写 | 每两周一次 |
| 系统管理员 | 账号管理、数据安全、问卷与理论库维护 | 按需 | 低频 |

### 1.4 创新点

**应用创新点**

- **场景创新**：切入"乡村教育 × 教师辅助"的交叉空白地带，把 AI 定位从"测评机器"改为"有理论支撑的教研助手"。
- **闭环创新**：打通"采集—评估—理论—干预"四段链路，干预建议先检索专业心理学理论再结合个体数据生成，做到有据可查、可追溯到理论来源。
- **低负担设计**：问卷单次 3 分钟以内，配合多模态日常记录，用"高频轻量"替代"低频重负"。

**技术创新点**

- **多模态数据融合**：结构化问卷数据与非结构化文本记录统一编码后，进入同一评估链路进行风险推理。
- **RAG + 规则双引擎**：规则引擎硬兜底 + 大模型语义推理的双通道，避免纯 LLM 方案在高危场景下的漏报。
- **理论可溯源**：每条干预建议携带来源理论标签与引用片段，解决 AI 建议"不可信、不敢用"的问题。

## 二、需求分析

### 2.1 功能需求

| 编号 | 功能模块 | 功能描述 | 优先级 |
|---|---|---|---|
| F1 | 账号与角色权限 | 教师注册/登录、班级创建、学生名册导入、按角色隔离数据 | P0 |
| F2 | 轻量化心理问卷 | 3 分钟内完成；支持匿名/实名开关；含标准量表精简项 | P0 |
| F3 | 多模态日常记录 | 文字速记 / 语音转文字 / 课堂行为标签三合一快速录入 | P0 |
| F4 | AI 心理评估引擎 | 问卷与记录统一送入 Agent，输出风险等级、类型、关键证据句 | P0 |
| F5 | 班级心理晴雨表 | 三色风险分布、趋势折线、异常波动预警、共性诱因归纳 | P0 |
| F6 | 个体干预方案生成 | 分步建议 + 沟通话术 + 观察指标 + 转介建议，附理论来源 | P0 |
| F7 | 心理学知识库检索 | 关键词 / 自然语言检索专业理论条目 | P1 |
| F8 | 家校沟通辅助 | 一键生成家长沟通要点与注意事项（分风险等级） | P1 |
| F9 | 数据导出与报表 | 导出班级晴雨表 PDF、个体方案 Word、月度统计 Excel | P1 |
| F10 | 隐私与安全 | 敏感字段加密、访问日志、数据脱敏展示、一键删除 | P0 |

### 2.2 非功能需求

- **性能**：单次 AI 评估响应 ≤ 8 秒；班级（50 人）批量评估 ≤ 60 秒；页面首屏 ≤ 2 秒。
- **可用性**：问卷页面适配低端安卓机与 4G 弱网，采用渐进式保存，断网不丢答案。
- **安全合规**：遵循《个人信息保护法》与未成年人个人信息保护相关规定，学生心理数据属敏感个人信息，需单独同意、最小必要采集。
- **兼容性**：Chrome / Edge / Safari 主流版本；移动端浏览器可用。

### 2.3 设计约束与取舍

| 约束 | 取舍 |
|---|---|
| 乡村学校网络条件差 | 前端零框架依赖、单页体积小、无外部字体与 CDN 依赖 |
| 教师非技术用户 | 交互不超过三次点击到达核心结论，术语尽量口语化 |
| 评委需在线体验 | 提供纯静态演示站，无需后端即可完整走通主流程 |
| 隐私合规 | 演示环境全部使用脱敏模拟数据，真实数据不进演示站 |

## 三、系统架构设计

### 3.1 总体架构

系统采用分层架构，自下而上分为数据层、AI 智能层、应用层、表现层。

```
┌──────────────────────────────────────────────────────────┐
│  表现层   教师端 Web（原生 JS + 纯 CSS + SVG 图表）        │
├──────────────────────────────────────────────────────────┤
│  应用层   账号权限 / 名单管理 / 问卷 / 记录 / 报表         │
│           演示环境：浏览器内运行                            │
│           线上环境：Serverless 函数（/api/*）               │
├──────────────────────────────────────────────────────────┤
│  AI 智能层 ① 规则引擎（高危硬兜底）                         │
│            ② 语义推理（大模型 API）                         │
│            ③ RAG 检索（向量化 + 理论库）                    │
│            ④ 方案生成（结构化输出 + 理论回填）               │
├──────────────────────────────────────────────────────────┤
│  数据层   演示环境：静态脱敏数据                            │
│           线上环境：云数据库 + 向量库 + 对象存储             │
└──────────────────────────────────────────────────────────┘
```

### 3.2 技术选型

| 层次 | 组成 | 技术选型 | 选型理由 |
|---|---|---|---|
| 表现层 | 教师端 Web、学生端轻量页 | 原生 HTML/CSS/JavaScript + SVG | 无框架依赖，单页体积小、首屏快，弱网与低端机可用；SVG 绘制趋势图，无需引入图表库 |
| 应用层 | 业务逻辑、权限、数据网关 | 演示：浏览器内运行；线上：Serverless 函数 | 演示环境零后端即可跑通全流程，降低评审体验门槛；线上用 Serverless 免运维 |
| AI 智能层 | 规则引擎、语义推理、RAG、方案生成 | 规则引擎（自研）+ 大模型 API + 向量检索 | 规则引擎可解释、可审计、硬兜底；大模型负责语义推理；两者互补 |
| 数据层 | 业务数据、理论库、文件 | 演示：静态 JSON；线上：云数据库 + 向量库 + 对象存储 | 演示环境数据量小，静态化最稳；线上按需扩展 |

### 3.3 数据模型（线上环境）

| 表名 | 关键字段 | 说明 |
|---|---|---|
| `user` | id, name, role, class_id, password_hash | 教师/管理员账号，角色隔离 |
| `student` | id, name, class_id, gender, is_left_behind, encrypted_meta | 学生基础信息，敏感字段加密 |
| `questionnaire` | id, student_id, batch_id, answers_json, score, created_at | 每次问卷作答记录 |
| `record_daily` | id, student_id, type, content, tags, created_at | 多模态日常记录 |
| `assessment` | id, student_id, risk_level, risk_type, evidence, model_ver | AI 评估结果，保留模型版本便于追溯 |
| `intervention` | id, assessment_id, steps_json, theory_refs, status | 干预方案与理论引用、执行状态 |
| `class_weather` | id, class_id, period, green_cnt, yellow_cnt, red_cnt, trend_json | 班级晴雨表数据 |

### 3.4 接口设计（线上环境）

| 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `/api/auth/login` | POST | 账号、密码 | token、角色、班级 |
| `/api/questionnaire/submit` | POST | studentId、batchId、answers | 作答 ID、初步得分 |
| `/api/record` | POST | studentId、type、content、tags | 记录 ID |
| `/api/ai/assess` | POST | text（记录文本）、answers（问卷作答）、theories（理论库）、studentName | 风险等级、类型、判定依据、干预步骤、理论来源、命中规则 |

## 四、AI 技术方案

### 4.1 选型理由

| 技术组件 | 选型 | 选型理由 |
|---|---|---|
| 大语言模型 | OpenAI 兼容的国产大模型 API（实际接入 `deepseek-v4-flash-0731`） | 中文语境与青少年心理文本理解能力好；API 按量付费、无部署门槛；国内访问稳定、合规可控。**不选纯本地小模型**：7B 以下模型在专业领域推理上幻觉严重，干预建议不可用 |
| Agent 编排 | 轻量自研编排（演示）/ Dify 或 LangChain（线上） | 演示环境自研确定性引擎，保证评审期间稳定可复现；线上用编排框架便于扩展与可视化调试 |
| 向量化与检索 | 演示：关键词召回 + 共现打分（零依赖）；线上：bge-m3 或 text2vec-base-chinese + 向量库 | 演示环境不引入向量模型，保证零依赖、可复现；线上换向量检索提升召回 |
| 规则引擎 | 自研关键词 + 正则 + 权重评分 | 高危信号不容许任何不确定性，必须硬触发；规则可解释、可审计，便于向评委说明安全设计 |
| 前端 | 原生 HTML/CSS/JS | 无构建步骤、无依赖，任何静态托管即可部署，评审体验零门槛 |

### 4.2 集成方式

- **统一 AI 网关**：应用层不直接调用大模型，统一经 `/api/ai/*` 网关转发，便于统一鉴权、限流、缓存与模型替换。
- **提示词工程**：系统提示词内置心理教师角色设定、青少年保护原则、禁止下诊断结论的红线约束；输出强制 JSON Schema，便于前端渲染。
- **RAG 流程**：理论库条目预先切片并标注关键词 → 评估时按记录文本与作答召回 Top-K 条目 → 将其“干预要点”拼入提示词 → 生成建议并回填引用来源。（演示环境用关键词召回 + 共现打分，线上可换向量检索。）
- **异步任务**：班级批量评估走队列，避免 HTTP 超时。

### 4.3 Agent 工作流

```
学生数据（问卷 + 日常记录）
        │
        ▼
  ① 规则引擎硬筛查 ──命中高危──▶ 直接升级红色预警 + 提示转介
        │（未命中）
        ▼
  ② 特征归一化（记录文本 + 问卷作答统一编码）
        │
        ▼
  ③ 大模型语义推理（风险等级 / 风险类型 / 证据句）
        │
        ▼
  ④ RAG 理论检索（按风险类型召回心理学理论 Top-K）
        │
        ▼
  ⑤ 干预方案生成（分步建议 + 沟通话术 + 观察指标 + 理论引用回填）
        │
        ▼
  ⑥ 结果落库 → 刷新班级晴雨表 → 推送班主任
```

**关键设计**：规则引擎与语义推理**串行且规则优先**——输入先过规则通道，命中高危则**短路返回红色预警、不调用大模型**（既保安全又省额度）；未命中才进入语义推理。任一层级判定为高危即升级风险等级，确保 AI 的不确定性不会导致漏报。

### 4.4 优化策略

| 优化方向 | 具体做法 | 预期效果 |
|---|---|---|
| 降低幻觉 | 强制结构化输出 + 理论引用回填 + 规则引擎兜底 | 干预建议可追溯，高危不漏报 |
| 降低成本 | 相同输入结果缓存；问卷评分等确定性计算不调用大模型；短文本小模型、复杂推理大模型分级调用 | API 费用下降 40% 以上 |
| 提升速度 | 流式输出 + 风险等级先行返回、方案异步补全；理论库常驻内存 | 首屏反馈 ≤ 3 秒 |
| 提升准确率 | 历史案例构造 Few-shot 示例；建立教师反馈回路，人工标注结果回灌 | 风险识别准确率逐周提升 |
| 安全护栏 | 输入侧敏感词检测、输出侧违规内容过滤、未成年人数据脱敏后再送模型 | 满足合规要求，避免隐私外泄 |

### 4.5 效果评估方法

- 构造 30–50 条脱敏模拟案例（覆盖绿/黄/红三色），由团队与指导教师人工标注基准，计算风险等级判定准确率与召回率（**重点看红色召回率，目标 100%**）。
- 对干预方案做人工可读性评分（1–5 分），统计"理论引用是否准确""动作是否可执行"两个维度。
- 记录平均响应时延与单次调用成本，形成优化前后对比表。

## 五、核心功能实现

### 5.1 规则引擎（硬兜底通道）

规则引擎是本系统安全设计的核心。其职责是：**对任何输入文本做高危信号硬筛查，命中即升级风险等级，不经过大模型判断**。

```
R-HARD-1  自伤/自杀意念   ["伤害自己","自杀","不想活","活不下去","结束生命"]   → 红色 · 硬触发
R-HARD-2  绝望感          ["没人能帮我","没有希望","绝望"]                     → 红色 · 硬触发
R-HARD-3  同伴关系风险    ["被欺负","被打了","校园欺凌","没人跟我玩"]           → 黄色
R-HARD-4  亲子分离应激    ["爸妈不在","留守儿童","想爸妈","没人管我"]           → 黄色
R-HARD-5  睡眠困扰        ["睡不着","失眠","做噩梦"]                          → 黄色
```

规则命中记录会随评估结果一并输出（含规则编号、类型、命中关键词、是否硬触发），前端以标签形式展示，使判定过程**完全可审计**。

### 5.2 问卷评分

10 题轻量问卷，每题 0–3 分，按维度聚合（情绪 / 睡眠 / 自我 / 焦虑 / 社交 / 学业 / 高危）。其中第 9 题（"我想过伤害自己"）为**高危筛查项**，一旦作答非"完全没有"，即触发红色等级。

### 5.3 RAG 理论检索

理论库当前收录 6 条核心心理学理论条目：

| 编号 | 理论 | 主要适用风险类型 |
|---|---|---|
| T1 | 依恋理论 | 亲子分离、留守儿童、社交回避 |
| T2 | 认知行为疗法（CBT） | 消极认知、自我否定、情绪低落 |
| T3 | 留守儿童心理韧性模型 | 韧性不足、适应困难 |
| T4 | 情绪 ABC 理论 | 易激惹、冲动、挫折应对 |
| T5 | 社会支持理论 | 社交退缩、孤立 |
| T6 | 马斯洛需求层次理论 | 底层需要缺口、动力不足 |

检索采用**关键词召回 + 文本共现打分**，按风险类型与证据文本打分排序，返回 Top-K 条目，并将其"干预要点"注入方案生成环节。

### 5.4 干预方案生成

方案生成遵循"**等级决定框架，理论决定动作**"的原则：

1. 风险等级决定基础动作框架（红色 → 立即响应 + 安全兜底 + 转介跟踪；黄色 → 重点关注 + 观察记录；绿色 → 常规关注）；
2. 召回的每条理论追加针对性动作（如召回依恋理论 → 补足替代性支持关系；召回 CBT → 认知觉察练习）；
3. 每条建议携带理论来源标签，前端可展开查看理论依据。

### 5.5 班级晴雨表

- **三色分布**：按学生个体风险等级聚合，输出绿色/黄色/红色人数与占比。
- **趋势折线**：近 8 周三色人数变化，纯 SVG 绘制，无图表库依赖。
- **共性诱因归纳**：对风险学生做群体特征聚类，输出如"留守儿童群体风险聚集（红色与黄色学生中留守儿童占比 82%，显著高于班级比例 40%）"等结论。

## 六、测试与部署

### 6.1 测试策略

### 6.3 部署方案

演示站前端为纯静态页面，可部署到任意静态托管平台；线上 AI 能力由仓库根目录 `functions/` 下的 Serverless 函数随站一起部署（无需单独部署后端）：

| 平台 | 命令 | 特点 |
|---|---|---|
| Cloudflare Pages | `wrangler pages deploy web` | 免费、无需备案、无 IP 访问限制；自动上传 `functions/` |
| Vercel | `vercel deploy web --prod` | 免费、部署简单 |
| Netlify | `netlify deploy --dir=web --prod` | 免费、支持表单与函数 |

**评审可用性保障**：

- 页面本身**零后端依赖**；AI 能力不可用时（未配密钥 / 服务不可达）**自动降级**为浏览器内本地确定性引擎，页面不会白屏；
- 部署平台自带 CDN 与 HTTPS，无并发限制；
- 评审账号在登录页直接公示，无需额外配置。

### 6.4 隐私与安全设计

- **数据脱敏**：演示环境全部使用模拟数据；线上环境敏感字段加密存储，展示层脱敏。
- **最小必要**：仅采集评估必需的字段；学生可匿名提交。
- **访问控制**：按角色隔离数据，班主任仅可见本班，心理教师可见全校。
- **审计留痕**：敏感数据访问记录日志。
- **数据可删**：支持一键删除个人数据。
- **密钥安全**：大模型 API Key 仅存于服务端环境变量，前端代码不含任何密钥。
